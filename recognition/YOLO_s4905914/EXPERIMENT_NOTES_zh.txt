配置仍是草案

n 是预先指定的主模型，s 是对照。两者都从各自原始 COCO 权重开始，
同划分、同 60 轮、640 输入、batch=16、FP32、seed=3710。
固定 AdamW，基础学习率 lr0=0.001；线性调度 lrf=0.01，warmup_epochs=3。
按固定版本的实际索引，第 60 轮学习率为 0.0000265，并非 0.00001。
之前“最后降到初始值的 1%”是过于简化的描述，现已修正。
只开左右/上下翻转，关闭 Mosaic、混合图片、颜色扰动和过采样。
这不是已经证明更好的方案，也不是单独检验某种增强效果的消融实验。
以后如果增加对照，应固定其余条件，单独改变一个因素。

老师回复前，完整真实训练入口保持关闭；小型人工数据测试可以运行。

你应该能讲清的五个概念

1. Epoch、batch 与 optimizer step

epoch 是遍历一轮训练集；batch 是一次送入模型的一组图片；optimizer
step 是实际更新一次参数。它们不是同义词。768/16=48 批/轮。
本配置关闭梯度累积，每批调用一次优化器，所以 60 轮计划调用 2,880 次。
这里数的是 step 调用。当前 warm-up 第一批学习率为 0，可训练参数在
这次调用中不变；不能说每次 step 都必然改变参数。
其他配置如果累积 4 批才更新，step 数就不会等于 batch 数。

2. AdamW 与学习率

AdamW 是更新参数的方法，learning rate 决定每次调整的大致步幅。
学习率太大或太小都可能影响学习；不能只凭名字判断哪个优化器最好。
这里写死它，是为了让 n/s 的比较条件明确，而不是证明它最适合此数据。

3. Checkpoint

checkpoint 是保存的模型状态。last.pt 是最后一轮，best.pt 根据事先
声明的 validation 指标选出。我们选择 validation mAP50:95 最高的
checkpoint。最高 mAP 的那轮，不一定也是恶性 Recall 最高的那轮。
不能看完各项结果后再挑一个最有利的“最佳”定义。
固定版本在训练期间先把返回的验证分数保留到小数点后 5 位，再进行
比较；该精度下并列时保留较晚一轮。新增记录保存实际选择时用的分数。

4. 模型选择和阈值选择是两件事

checkpoint 选择决定用哪一组参数；阈值选择决定哪些预测被保留。
二者都只在 validation 上做。草案用“良性图误警报率不超过 10%”作
课堂比较条件，再在满足条件的阈值里尽量提高恶性检测 Recall。
124 张良性图最多可误警报 12 张；13/124 已超过 10%。
这个预算没有临床验证，不能据此推荐真实诊疗。若没有可行阈值，就报告
没有可行点；不能悄悄放宽限制，再宣称达标。

5. Smoke test 与模型效果

smoke test 是一个小型“整条流程能否跑通”的检查。这次使用简单人工
图片检查两类输出、梯度更新、保存/重载、指标计算和预测展示。
即使人工图 mAP 很高，也不能据此说模型能检测皮肤癌。
单元测试通过、流程能运行、真实模型表现好，是三层不同的证据。

两个容易混的 IoU

NMS IoU=0.7：比较两个预测框是否足够重叠，决定是否抑制较低分框。
匹配 IoU=0.5：比较预测框和 GT，结合类别判断是否成为 TP。
课程目标 IoU≥0.8：还需确认统计分母；不能用 TP-only 平均值冒充全体表现。

验证集为什么也会被过拟合

validation 不参与反向传播，但它会影响我们选择哪轮 checkpoint、哪个
阈值和哪些设置。反复看它的结果并修改方案，会间接让最终方案越来越
适合这批样本。预先写好比较规则、限制尝试次数和如实记录所有对照，
能减少选择偏差，但不能保证对新病例有效。重新划分已看过的数据，也
不能使它变回全新盲测。

训练中的四个步骤

Forward（前向计算）：把图片送入网络，产生预测。
Loss（损失）：用标签计算预测的差距，是训练目标，不等同于 Recall。
Backward（反向传播）：计算 loss 对可训练参数的梯度。
Optimizer step（优化器更新）：根据梯度和优化器状态修改参数。

loss.backward() 本身不会执行优化器的参数更新；optimizer.step() 才
执行这一步。常规训练还需要适时清空梯度，否则梯度可能累积。
注意 BatchNorm 的运行均值等不是可训练参数，训练模式下前向时就可能
改变；所以不能把“不更新可训练参数”扩大成“模型所有状态都不变”。

预处理：resize 与 padding

Resize 是改变图片尺寸；padding 是补边。例如 400×200 的图片等比例
缩放成 640×320，再上下各补 160 像素，得到 640×640，形状比例保留。
若原图中心为 (200,100)，缩放补边后变成 (320,320)。预测框映射回来时，
必须先减去补边，再除以缩放倍数，不能直接按整个方形画布等比例缩回。

只检查配置都写 imgsz=640 还不够。原验证加载路径先缩放并向上取整，
预测路径直接用 letterbox 并四舍五入，实际像素可能不同。现在评估
统一为一次 letterbox，8 种人工尺寸/分辨率组合已经检查像素相同及框
还原正确。这不能证明旧恶性错误由预处理引起，也不代表模型准确率提高。

本机通过与学校 GPU 通过是不同的证据

本机人工测试证明这里的程序能执行前向、反向和更新。preflight.py 已
学校 GPU 的 batch=16、640 输入检查已由作业 669120 完成。其两步
AdamW 检查也没有包含完整 trainer 的 EMA、数据工作进程和验证阶段，
所以即使通过，也不保证完整训练一定有足够显存。检查耗时不能当推理 FPS。

接着学：learning rate（学习率）

梯度是局部变化率；学习率控制优化器调整参数的大致步幅。为了先理解
它，用没有动量、没有权重衰减的简单 SGD 举例：

新参数 = 旧参数 − 学习率 × 梯度。

例如旧参数 0.5、梯度 2、学习率 0.1，则新参数为 0.3。
若学习率改成 0.01，同一梯度下参数变为 0.48，调整幅度更小。
并不是学习率越大越好；过大的步幅可能越过较好的位置或使训练不稳定。
梯度只描述当前位置的局部关系，一次有限更新不保证损失一定下降。

项目实际用 AdamW。它还使用梯度的一阶/二阶历史估计和权重衰减，不能
把上面的简单 SGD 公式直接当作本项目每次更新的精确计算公式。当前
lr0=0.001 是初始设置；warm-up 与学习率调度会改变训练中的实际学习率。

Warm-up（预热）与 scheduler（学习率调度）

Warm-up 在训练初期逐渐增大学习率，减少一开始调整过猛的可能。后续
scheduler 可以逐步减小学习率，让后期调整的步幅更小。它们是训练策略，
不是已经充分收敛或模型效果更好的证明。

当前每轮 48 批，3 轮对应 144 个批次间隔。上游 warm-up 判断包含索引
144，所以第四轮第一批仍进入预热分支。预热目标同时跟随按轮下降的
学习率，因此本配置的实际峰值约为 0.0009603，而不是完整达到 0.001。
第 60 轮用的索引是 59，倍率为 (1−59/60)×0.99+0.01=0.0265。

AdamW 的 beta1=0.9、beta2=0.999 在这里保持不变。配置中的
warmup_momentum=0.8 没有改变它们；不能看到参数名就认为它一定生效。
新增 optimizer_steps.jsonl 记录实际值，让报告可以和运行记录核对。

学习率为 0 时，当前 AdamW 调用不会改变可训练参数，但内部梯度历史和
步数仍可变化。因此，“参数没有变化”不能扩大成“程序什么都没做”。

EMA：Exponential Moving Average，指数移动平均

训练过程中，一份模型参数由优化器更新；EMA 是同一模型参数的一个
移动平均副本。当前上游代码使用 EMA 做训练期间的验证，并保存它。
这样可以平滑参数随训练变化的波动，但不保证验证效果更好。

用固定系数的简化例子说明：
新 EMA = 0.9 × 旧 EMA + 0.1 × 当前训练参数。
如果旧 EMA 是 0.6，当前参数是 1.0，新 EMA 就是 0.64。
0.9 只是教学例子；本项目上游实现的系数随更新次数逐渐变化，公式是
0.9999 × (1 − exp(−更新次数/2000))。EMA 本身不通过反向传播学习，
它跟随训练模型更新，也会处理浮点型状态缓冲区。

FP32 训练、文件保存和重新加载要分开说

当前训练参数与 EMA 参数在内存中是 FP32；固定库保存文件时把 EMA
副本转成 FP16。重新加载时又变为 FP32，但转回更高精度不能找回保存时
已经舍入掉的数值。这不是新增的训练策略，不能把它直接认定为分类错误
的原因。正式评估应明确针对哪一个保存文件，并记录文件哈希。

训练结束时，上游会清除 optimizer 状态，把 checkpoint 的 epoch 字段
改成 −1。这个值不表示“训练了负一轮”。现在 checkpoint_history.jsonl
和 run.json 单独保存最佳轮次、选择分数和 EMA 来源，供报告核对。
best.pt 与 last.pt 是不同选择规则；训练完成后被清理的这两个文件，也
不能当作包含完整优化器状态、可无缝恢复原训练的快照。

迁移学习、微调和冻结

预训练（pretraining）：先在来源任务上学习参数；本项目使用原始 COCO
权重作为起点。迁移学习（transfer learning）：把来源任务学到的部分
表示用于新任务。微调（fine-tuning）：在新任务上继续更新这些参数。
冻结（freezing）：不让指定参数参与优化器学习更新。预训练不等于冻结。

本次两类模型的实际检查发现，n/s 的 Backbone、Neck 和框回归状态都
成功复用 COCO 来源，并且这些部分的参数仍允许更新。新分类输出要
学习良性/恶性的定义。n 因分类分支内部宽度改变，该分支的可训练参数
全部重新初始化；s 只需重新初始化三个尺度上的最后分类输出层。
“重新初始化”包括随机权重、固定初值或特定偏置初始化，并非所有数
都是随机数。新模型不是完全从零训练，也不是直接拿 COCO 标签判良恶性。

模型日志中的 319/355 或 349/355 是状态条目数，包括统计缓冲区；不是
准确率，不是可训练参数数量，也不是已经学会本任务的比例。实际代码
和逐项比对见 audit_initialization.py 与根目录 MODEL_COMPONENTS_zh.txt。
目前未冻结 Backbone；只有 DFL 解码积分的 16 个固定坐标参数保持冻结。

SHA-256（文件校验值）

可把它理解成文件内容的指纹。传输前后同一文件的校验值一致，可以
检查内容有没有变化；它不能说明里面的医学标签正确，也不能证明模型
准确。文件完整、程序正确、实验设计合理、模型表现好，是不同层次。
