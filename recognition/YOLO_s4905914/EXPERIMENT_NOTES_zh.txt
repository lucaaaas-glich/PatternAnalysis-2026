新项目的训练配置与学习笔记
2026-10-17

这轮准备了什么

代码已经把“分组清单 → 数据检查与加载 → 两类 YOLO → 训练保存 →
validation 选择阈值 → 锁定后的补充评估 → 单图预测”连接起来。
真实 ISIC 数据还没有开始新训练。人工测试图只用于发现程序接口问题。

配置仍是草案

n 是预先指定的主模型，s 是对照。两者都从各自原始 COCO 权重开始，
同划分、同 60 轮、640 输入、batch=16、FP32、seed=3710。
固定 AdamW，初始学习率 0.001；线性降到初始值的 1%，前 3 轮 warm-up。
只开左右/上下翻转，关闭 Mosaic、混合图片、颜色扰动和过采样。
这不是已经证明更好的方案，也不是单独检验某种增强效果的消融实验。
以后如果增加对照，应固定其余条件，单独改变一个因素。

老师回复前，完整真实训练入口保持关闭；小型人工数据测试可以运行。
代码已实现第三方模型接入，但老师是否接受这种 modules.py 包装仍未确认。

你应该能讲清的五个概念

1. Epoch、batch 与 optimizer step

epoch 是遍历一轮训练集；batch 是一次送入模型的一组图片；optimizer
step 是实际更新一次参数。它们不是同义词。768/16=48 批/轮。
本配置关闭梯度累积，每批更新一次，所以 60 轮计划更新 2,880 次。
其他配置如果累积 4 批才更新，step 数就不会等于 batch 数。

2. AdamW 与学习率

AdamW 是更新参数的方法，learning rate 决定每次调整的大致步幅。
学习率太大或太小都可能影响学习；不能只凭名字判断哪个优化器最好。
这里写死它，是为了让 n/s 的比较条件明确，而不是证明它最适合此数据。

3. Checkpoint

checkpoint 是保存的模型状态。last.pt 是最后一轮，best.pt 根据事先
声明的 validation 指标选出。我们选择 validation mAP50:95 最高的
checkpoint。最高 mAP 的那轮，不一定也是恶性 Recall 最高的那轮。
不能看完各项结果后再挑一个最有利的“最佳”定义。

4. 模型选择和阈值选择是两件事

checkpoint 选择决定用哪一组参数；阈值选择决定哪些预测被保留。
二者都只在 validation 上做。草案用“良性图误警报率不超过 10%”作
课堂比较条件，再在满足条件的阈值里尽量提高恶性检测 Recall。
124 张良性图最多可误警报 12 张；13/124 已超过 10%。
这个预算没有临床验证，不能据此推荐真实诊疗。若没有可行阈值，就报告
没有可行点；不能悄悄放宽限制，再宣称达标。

5. Smoke test 与模型效果

smoke test 是一个小型“整条流程能否跑通”的检查。这次使用简单人工
图片检查两类输出、梯度更新、保存/重载、指标计算和预测展示。
即使人工图 mAP 很高，也不能据此说模型能检测皮肤癌。
单元测试通过、流程能运行、真实模型表现好，是三层不同的证据。

两个容易混的 IoU

NMS IoU=0.7：比较两个预测框是否足够重叠，决定是否抑制较低分框。
匹配 IoU=0.5：比较预测框和 GT，结合类别判断是否成为 TP。
课程目标 IoU≥0.8：还需确认统计分母；不能用 TP-only 平均值冒充全体表现。

当前不能声称的事

- 尚无新 ISIC 性能结果，也没有 GPU 内存/速度测量。
- 不能说当前子集完全患者独立；708 张仍缺 patient_id。
- 重新划分、清理文件都不恢复盲测状态。
- 采用 YOLOv8/COCO 权重不等于自行实现了卷积、C2f、Detect 或 loss。
- confidence 不是患癌概率；图片警报不是活检次数。
